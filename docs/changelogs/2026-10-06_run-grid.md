# 2026-10-06: run_grid, dial grids as runtime data

**Files changed:** `src/cilib/environments/spec.py`, `src/cilib/core/schedule.py`,
`src/cilib/metrics/reducers.py`, `src/cilib/lab/analysis/bootstrap.py`, docstrings in
`src/cilib/core/scan.py`, `core/time.py` and `lab/paradigms`, `src/cilib/CLAUDE.md`,
`ROADMAP.md`. New tests: `environments/tests/test_run_grid.py`,
`lab/analysis/tests/test_bootstrap.py`, one in `runs/tests/test_record.py`. New script:
`experiments/perf_baseline/grid_calls.py`.

## What

`EnvSpec.run_grid` runs a grid of dial values times a batch of seeds as one compiled
program. A dial is an array entry of the initial `global_attrs`; its values reach the
program as inputs, so a new grid of the same shape needs no new compile. With the
default `batch=1` every cell is bit-identical to `run_reduced_batch` on a spec built
with that cell's value, apart from reducer init values the scan never overwrites, which
can be one float32 ulp off. Also added: a string `onset` for `scheduled` that reads
the switch-on step from `global_attrs`, the `at_step` reducer, and `paired_diff_ci`.
No environment, mechanism or existing number changed.

## Why

Every sweep driver built one spec per grid cell and paid a compile per cell. On a
25-cell `ledger_society` grid with 8 seeds and T = 400, the loop took 44.7 s and
`run_grid` took 3.5 s on its first call, 1.5 s on a repeat. One machine, one run each,
no interval; method and provenance in `docs/run-grid-design.md`.

## The rule it changes

`src/cilib/CLAUDE.md` said config never goes in `global_attrs`. It now says structural
config is closed over, swept dials are 0-d arrays in `global_attrs`, and Python scalars
never go there. Several docstrings said `global_attrs` as a whole is static; since the
2026-03-30 pytree fix only its Python-scalar entries are.

## Cells one at a time

The first version put the cells under a `vmap`. On the grid above that left 7 of 25
cells off the loop's numbers, by float32 rounding, the effect that separates `run` from
`run_batch`. A `lax.map` over cells is bit-identical and still far faster than the
loop, so it is the default; `batch > 1` keeps the vectorized option. That version's
`chunk` argument is gone, since `lax.map` holds one batch of cells in memory at a time.

## Red team

Three attackers. They found two grid keys that should be refused, a silent truncation
of float onsets, three test gaps, an edge case in `paired_diff_ci`, and the reducer
init exception above. All are fixed or recorded, with answers, in the design doc's
red-team record.
